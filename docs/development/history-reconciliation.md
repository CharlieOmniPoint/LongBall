# Participation correction and reconciliation implementation

Introduced in `synthetic-live-3` and retained by the current `synthetic-live-4` engine, this flow supports immutable retrospective lineup and availability corrections, voids and explicitly reviewed missing participation entries. A current controller supplies the reviewed source revision, actual integer active-time boundary and evidence reason. The reducer rebuilds participation and availability targets from retained facts rather than manufacturing monotonic clock samples. It preserves actual half lengths, the second-half starting lineup, raw event/audit history, immutable player snapshots and the original completion timestamp.

Each player partitions the actual active match time into playing, available bench and unavailable intervals. Position totals equal playing time. Real vacant places remain a visible shortfall; a return to availability never automatically puts someone on the pitch. Invalid allocations, unavailable play, stale drafts, cross-half movement and contradictory credited-scorer evidence reject the change without mutation. A conflicting goal must be corrected explicitly first. Historical half/clock changes are not inferred: both-half/trusted-clock evidence needs separate review.

The native connected controller and fictional browser rehearsal expose History corrections and reconciliation. Managers can open a recorded fact or review a missed event, enter actual time and allocation/player/reason, inspect the validated before/after player-time and vacancy preview, then separately confirm the canonical compensating event. The normal durable controller outbox retains its exact identity, sequence, clock evidence and retry body. Native recording still requires the protected journal's device check and held controller. A real-account browser never opens this private controller cache.

For contradictory old-device submissions, `/reconciliation` supplies ordered original evidence/digests and accepted revision. Explicit duplicate, retained-dispute or confirmed-event-import proposals validate against that exact accepted checkpoint. Source bytes remain read-only; import intents require independent explicit boundaries and reasons. Preview-only identifiers consume no canonical device sequences. Preparing a proposal binds the server-verified actor, accepted-state digest and immutable source digests. The separate protected, account/team/season/match-scoped review document retains the exact HTTP body/key before transmission, survives reload and validates the saved receipt. A proposal never clears quarantine, overwrites accepted play or creates controller authority.

The precise remaining Q08 decision is the canonical specification's request to **confirm who may approve unresolved history reconciliation**. The owner must define who can approve imported old-device evidence, duplicate dispositions and remaining disputed history, plus required evidence and policy version. Assigned-manager membership by itself does not approve this authority. The default service can prepare/validate proposals; final `/reconciliation/apply` returns `503 Q08_AUTHORITY_UNAPPROVED`. No client self-approval switch or guessed server event stream exists. Later approved application must consume deliberately prepared current-controller canonical wire events atomically with their exact sequence/checkpoint and proposal link; the server must not invent a replacement device stream.

Engine migration is explicit. The archived fictional v2 fixture was generated by the reducer at commit `3b2d83d` and v3 reproduces its accepted projection exactly, covering two halves, fractional clock input, pause/resume, lineup, captured availability, goals, corrections and void. This is bounded regression evidence, not a proof for every malformed historic payload. Existing accepted state/raw events remain retained. Pending v2 envelopes are never relabelled: mixed-engine capture/replay is blocked, while their original upload/key can be retried and retained as `UNSUPPORTED_EVENT_VERSION` quarantine. Reserved device sequences never reset. A production migration of external legacy clients is not claimed by this fictional rehearsal.

Server-time evidence uses an actual challenge/acknowledgement exchange against the current native continuous clock. A new controller, reboot or changed clock requires another exchange. Fictional browser use requires an explicit experiment acknowledgement. The exchange never blocks durable local capture and never authorizes competition sharing or changes awards policy. Its receipt is saved in the protected connected document, with retained receipt history. Only new envelopes in the same match/device/controller epoch/continuous session and original mapping lifetime attach the challenge ID. A new epoch clears the active mapping without deleting the receipt history or changing already queued envelope bytes. The actual HTTP client integration test follows the exchange through a JSON reopen, queued full-time event and service-derived trusted finish context under an explicitly fictional clock policy; a deliberately skewed device wall clock is ignored.
