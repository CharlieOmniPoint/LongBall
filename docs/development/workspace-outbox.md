# Connected workspace request recovery

`packages/application/src/workspace-outbox.ts` retains one exact non-controller request while its acknowledgement is uncertain. It covers preparation, own preparation, community and records commands. It does not count a queued ballot, extend a deadline, publish an image, approve a decision or change an expected server revision. Only a current authenticated service receipt can confirm the request.

The UI must commit the request through the existing `Journal`/`useDocument` before its first network attempt. The stored wire body and idempotency key are replayed exactly. Network failure, an unreadable reply, authentication/access uncertainty and retryable service errors retain the request. A verified acceptance or definite validation/revision refusal is committed before the UI announces its result. The exact settled candidate remains available for review; earlier projections remain in the same journal. A local persistence failure blocks another action and uses `useDocument.retry()` with the same local event.

The document namespace binds API, account, issuer, subject, team, season, role and own-player identity. A refresh generation is intentionally excluded so reopening can recover it. Replay requires a fresh authenticated `/me` response, current membership and an unlocked, unexpired sign-in for the same API and identity. Manager replay also requires verified adult stronger authentication. The service rechecks authority and the actual receipt deadline. There is no automatic background replay.

Durable private bodies require the native journal's real diagnostics: SQLCipher mode/version, a passed wrong-key probe and backup exclusion. Explicitly fictional browser review can use the synthetic browser journal. Production browser requests use memory only until a separately verified protected browser-storage design exists; closing that context can lose an unresolved request. Invitation acceptance remains a connected-only separate flow because the invite credential grants destination membership. Authentication, refresh, controller and upload credentials/headers are never stored in this outbox.

Pure tests cover close/reopen identity preservation, altered inputs, duplicate keys, cross-scope denial, expired/revoked membership, adult authority, locked/expired identity, uncertain replies, exact settled receipts, malformed records, credential rejection and storage evidence. They do not prove native encryption or operating-system backup exclusion: those require the existing native device checks.
