# Club administration and match-day expansion

Owner-requested changes from 24 October 2026 extend the existing native iPhone/Android application and connected browser review. They do not replace the original F01–F28 scope or approve a production release. The supplied [original build pack](../longball/LongBall_Mobile_Build_Pack_v0_1.md) remains unchanged; this document records the later instructions.

## Implemented review journeys

| Area | Expected behaviour |
| --- | --- |
| Formation | Manager opens Formation, chooses the playing format and enters a traditional pattern such as `4-4-2` for eleven a side or `3-2-1` for seven. The numbers count outfield players; one goalkeeper is implicit. A pitch shows position markers without player names/initials. The total must match the playing format before saving an existing versioned formation. |
| Formation advice | Available, eligible players and ranked preferences inform suggested shapes around 65% primary / 35% secondary position use. Capacity conflicts and missing secondary opportunities stay visible. Advice requires Manager review; it neither guarantees an impossible split nor changes accepted events, availability, lineups or substitutions automatically. |
| Administrative hierarchy | The existing demo Administrator represents Super Admin. A separate Club Admin scope manages its own clubs and creates teams there, with inherited Manager rights. Super Admin can create clubs and administer verified adult grants across the application. The wire role remains `administrator`; a server-owned `principal.administration` distinguishes `super` and `club`. A UI label/header cannot create authority. |
| Clubs, teams and reports | Club/team/season selection accommodates U5–U21 and multiple teams at each age. Club Admin sees only authorized clubs; Super Admin can select all. Club performance reports aggregate accepted completed games, merge canonical and archived revisions once, retain unknown scores, and support client sorting/filtering by team and age group. League name is optional free text, up to 120 characters. |
| Spectator invitations | Current users can issue a team/season-scoped spectator invitation, show a QR code or compose an email with its link. Team contribution restrictions and invitation expiry still apply. QR generation occurs locally. Email composition opens the user's mail application; a configured SMTP service and guaranteed delivery are not claimed. |
| Spectator PIN entry | The invitation holder chooses a username and four-digit PIN during first registration. Repeated digits/pairs, ascending/descending sequences including wrapping sequences and common easily guessed codes are refused. Salted scrypt verifiers and bounded login attempts protect the spectator-only identity. PIN authentication grants no Player, Manager or administrative authority. |
| Multiple spectator teams | Additional invitations can grant additional team/season access. A spectator selects a permitted team and optionally the player they follow. The connection catalogue contains only active player IDs/display names, without FA IDs, profiles, attendance or individual statistics. |
| Invitation requests | Someone without an account can choose a club/team/season and request Player or Spectator access. The request creates no account or membership. Staff can mark it handled or declined, then use the appropriate invitation/activation flow. Handling alone is not approval or an access grant. |
| Match-day reminders | A Manager controlling an active game sees the next advised substitution countdown and affected changes. Per-team settings configure warning lead time from zero to 300 seconds and foreground volume from 0 to 100%. Advice remains manual. Pause, backgrounding, clock uncertainty, loss of control and stale plans suppress inappropriate audio. See [substitution alert notes](substitution-alerts.md). |
| Player proforma | Manager downloads a genuine BIFF8/OLE Excel `.xls` workbook containing the scoped roster, edits it and previews the import. Existing players retain explicit IDs; names never merge identities. Formula/control-cell content, wrong-scope workbooks, invalid positions/duplicates and oversized imports are rejected before persistence. XLS handling is local and creates no spreadsheet hosting service. |
| FA details and team sheet | A Player can edit only their own optional FA player ID; Managers can edit team players. IDs preserve leading zeroes and are not credentials. Staff can upload, replace, view/download or remove a team-bound PDF FA sheet. The server validates genuine unencrypted PDF structure, one to 50 pages, a five MiB limit and absence of scripts, attachments and launch actions. Spectators/Players cannot download staff team sheets. |
| Goalkeeping | My Stats and staff player stats show known clean sheets. A completed accepted game contributes one for a player who spent positive active time in goal and had no opposition goal during those goalkeeper stints. An own goal benefiting the opposition counts as conceded. Final-score summaries and missing/ambiguous timing do not invent a clean sheet. |
| Opposition notes | After a recorded completed game, staff may save a capability rating from 1 to 5 and an optional note of at most 256 Unicode characters. Players can read the team's opposition notes; spectators cannot. These are manager-entered observations, separate from private player enjoyment reflections. |
| Role presentation | Spectator presentation uses blue and Super Admin presentation uses purple. Manager/Club Admin context, current team and simple sign-out remain available. Responsive phone/tablet modes and the simpler Player/Spectator journeys continue. |

## Authority, retry and history boundaries

Club/system administration is persisted independently from appointed coach membership. Inherited Manager scope does not consume one of the four appointed coach places. Revocation removes inherited access while preserving an independently appointed role. Grant targets must already have current verified adult identity and stronger authentication; no child/shared account is promoted. Super Admin changes to clubs or privileged grants require recent strong authentication, and the last Super Admin cannot be removed.

A subsequent actual SQLite/PostgreSQL regression found that ordinary coach revocation could target a Super Admin's inherited Manager row and freeze its controller/preparation access while the administrative grant remained. The pending correction rejects all inherited rows on the appointed-coach revocation route. Administrative grant removal remains the separate authorized path; neither the four-coach cap nor an independent appointed role is silently changed.

The [append-only PostgreSQL 025 policy](../../apps/api/migrations/postgresql/025_inherited_manager_authority.sql) restricts ordinary updates of inherited Manager rows. PostgreSQL is schema 25 with 45 RLS tables; SQLite remains schema 11. Original migration 021 is byte-identical to `aeefdbf`. Five focused actual SQLite/restricted-PostgreSQL checks passed, including in-place 024→025, verification failing closed and unchanged domain state. Full API/static/migration checks and a final corrected-source commit are pending; no final acceptance is claimed from this focused result.

Scoped writes recheck the current identity and authority. Team-sheet and opposition commands capture their source revision; stale edits fail instead of overwriting another device's work. Command IDs match the mutation idempotency header where the route requires it. Opposition receipts preserve exact retries. Invitation request decisions transition a pending request once; a repeated decision does not invent a second approval.

Past-game Player availability remains closed, recorded replies/attendance remain readable, and today/future unplayed games remain open without assuming that scheduled kickoff means completion. Existing fairness bands, goalkeeper exceptions, controller exclusivity, manual half endings, unknown historical values and publication decisions remain in effect.

Clean-sheet evidence uses accepted active-time intervals, including corrected history, and nonvoid opposition goal beneficiaries. A goal at the final whistle counts against the goalkeeper. Where a goal shares an exact goalkeeper-change timestamp and retained evidence cannot establish which keeper was responsible, the affected outcome remains unknown and is reflected in coverage. No score or missing event is silently reconstructed.
