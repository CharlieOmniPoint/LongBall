# Independent release and quality re-audit

The original SEC22, QL and reproducible-build sections exposed missing automation: the exact `db:migrate:check` command, continuous source checks, retained dependency/licence inventory and dependency/secret scanning. These are now implemented. [Observed results and limits](summary.json) are separate from future committed-source CI.

The actual migration command passed **16 tests across three suites**, including real PostgreSQL upgrades and retained-history refusal/rollback. It refuses to run without a disposable PostgreSQL selector, so a missing database cannot produce a misleading all-skipped success.

Gitleaks 8.24.3 is downloaded from its official release with fixed archive and executable SHA256 values. It scans tracked and nonignored untracked current files, not Git history. All unexpected findings fail. The reviewed exceptions bind exact source lines, rule and location for existing artifact/commit checksums and one ordinary sentence; there is no blanket evidence/test-path exclusion or inline suppression. Published reports contain allowlisted metadata only, never matched bytes.

The JavaScript inventory contains **363 resolved packages and 272 retained licence files**. Its generated SPDX 2.3 document passed the official 2.3.1 JSON schema after correcting an initial property-name error. This inventory includes development and optional dependencies; unavailable optional packages have no retained text. It is not a native OS/image SBOM or legal licence approval. Full generated documents/licence files remain under ignored `.local/quality/inventory` and are retained by the CI artifact step for three days.

The actual registry audit **failed** for two unpatched high-severity build-tool advisories: `node-forge` 1.4.0 and `braces` 3.0.3. Their latest registry versions remain vulnerable, and neither advisory supplies a patched release. A separate moderate `uuid` finding concerns buffer-taking v3/v5/v6 calls; the installed Xcode helper uses v4. No unsafe cryptographic patch, unsupported major override or advisory suppression was added. The pinned API-runtime and compiler package-lock audits passed; that narrower result does not turn the workspace gate green.

The new development workflow runs source, database, contract, export and browser checks even when the audit gate fails, then marks the quality job failed explicitly. Its separate production-image job uses a fresh public standard runner, unique private runtime selectors and no host ports. The prepared script refuses ordinary local execution so it cannot overwrite the development machine's retained secrets/volumes. Actual image acceptance remains pending until the workflow runs. Existing host schema15 media/paired-restore evidence remains separate; the new image job does not claim paired restore.

Release acceptance also needs the explicitly deferred physical-device matrix and operating decisions. In particular, SEC20/SEC21 account privacy capture/status is implemented, but verified fulfillment, account/media/processor deletion and a deletion ledger are incomplete. Q05/Q09/Q10 must establish verification authority and retention/operating rules before those actions can be implemented and enabled coherently. A successful screen, request receipt or report export is not proof of global erasure.
