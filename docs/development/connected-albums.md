# Connected game album selection

UI27/UI28 now use an explicit game selection rather than `community.matches[0]`. `ConnectedAlbums` consumes the current server-filtered community match/gallery DTO and a selection ticket bound to API, verified account issuer/subject, role/player, team and season. A scope mismatch is rejected synchronously; an ordinary same-scope refresh can preserve the choice. No first game is selected automatically.

Only games whose current DTO permits sharing appear. Album ordering uses the supplied played date/time, never upload time; unknown dates remain explicitly unknown. Date display uses the configured timezone, with the canonical Europe/London pilot assumption labelled explicitly while the community DTO has no timezone field. A regression covers midnight during British summer time and an alternate configured timezone. Counts include only the visible published gallery rows for that game, so private, pending, rejected or hidden-uploader items cannot inflate the album count. The selected album has a two-column photo list and a separate photo viewer. Thumbnail/full-image callbacks continue through the authenticated media gateway; the chooser itself creates no permission and does not approve Q21.

Uploads must capture their selected game and stable scope before asynchronous hashing, then retain that original target and request identity for every upload phase/retry. A retained request locks the chooser. Explicitly closing its in-memory capability keeps the private server record; it does not publish or delete an image. Same-scope upload/moderation refresh must keep the selected game above the temporarily unmounted DTO subtree.

Pure tests cover played-date ordering, published counts, withheld/orphan photo omission, explicit choice, all identity/scope boundaries, same-scope refresh, immutable upload targeting, spectator upload denial and ambiguous identities. The next browser proof in `scripts/connected-review.mjs` prepares separate generated fictional PNG uploads for two permitted games and checks their real HTTP metadata. Its isolated fictional API defaults are ports 4320 and 4321; startup refuses an unrelated listener or existing match history. With no configured scanner, both must remain private with `SCANNER_REQUIRED`, and published gallery counts must remain unchanged. No production photo-publication or antivirus claim follows from that test.

Static Pages review builds use `EXPO_PUBLIC_REVIEW_STATIC=1`: fictional journeys remain local, service URL inputs start empty, and same-origin/relative static-host addresses are rejected before authentication or network. A separately supplied API address or temporary combined API review link is required for connected service features. Native and combined-server defaults are unchanged.
