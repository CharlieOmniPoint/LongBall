# Full feature build and evidence register

Implementation checkpoint: 21 October 2026. The canonical pack and all F01–F28 remain the product target. This document records the expanded synthetic implementation after the initial M0 journey. Earlier scope/traceability documents describe the initial slice and must not be read as current full-feature completion. An implemented local control, browser interaction, API test and physical-device proof are different evidence.

The workspace contains one Expo/React Native iPhone/Android application, a phone-sized React Native Web review export, shared domain/application packages, a local Node/SQLite development API and a durable local worker. No paid service is needed for these local implementations. The fictional review and authenticated connected paths are separate execution modes. Production deployment and real child data remain gated; this is not a full integrated-pilot or release-complete claim.

## Execution modes and connected limits

The ordinary review export opens the fictional Roma journey and its explicit fictional role controls. A service workspace can exercise actual HTTP reads/writes against the deliberately configured development API. Those public fictional API identities are disabled in the production entry.

With `EXPO_PUBLIC_ENVIRONMENT=production`, the application enters `ConnectedApplication`: system-browser OIDC/PKCE sign-in, verified API identity/memberships, scoped connected preparation/reports/community and an encrypted native controller document. The OIDC browser cannot mount or persist a real-account controller cache because synthetic IndexedDB does not provide the native encryption/backup guarantees; authenticated workspace views stay in memory. Browser users can still exercise the full fictional controller against an explicitly synthetic service. Native credential, picker and controller source exists; there is no completed real identity-provider or physical-device end-to-end proof.

Controller documents are separated by API, issuer, account, team, season, match and device. The client verifies current manager identity before mounting a cache, checks downloaded scope, retains same-request canonical outbox identities and downloads the actor-bound accepted projection after upload. An authoritative access denial closes private cached details while preserving pending/rejected history.

Ordinary preparation/own-response/community/records requests now use a separate scoped journal document when the current storage evidence permits it: verified encrypted native storage, or explicitly fictional browser storage. The command bytes, idempotency key and original revision are saved before sending; replay checks fresh service identity and current access. A queued ballot is not counted before server acceptance. Unprotected real-browser connections use explicitly labelled memory-only retries; closing the screen loses those requests. Invitation acceptance remains an online destination flow. Thirteen helper tests cover exact reopen/replay, scope separation, current authority, receipt settlement, uncertainty, payload bounds and storage gates. The actual browser/HTTP response-loss/reload/exact-retry scenario passed on the final `f8f0a16481bae90ff4ebe5a3a137543c` export; physical native durability remains unproved.

Connected workspace responses and cached DTOs now bind API, account, issuer, subject, team, season, role, player and request generation at attachment and render. Auth-change, foreground and expiry guards close private views; own preparation also requires current same-player membership. Four pure boundary tests support these safeguards; real identity-provider and device acceptance remain open. Native connected attendance, saved-formation staging, goals, corrections and availability now have an editor using the canonical stream and a native-journal evidence gate. A native export or pure test does not prove that journey on an actual phone.

The richer local historical-result editor includes correction, known attribution and explicit unknowns; the connected result screen currently exposes a smaller add/read subset and labels unrecorded minutes explicitly. Invitation acceptance now accepts an explicit destination team/season without prior membership and switches scope only after service acceptance. Delivery/deep-link integration and real new-account activation remain open. Connected season rollover is explicitly refused until assignments and spectator renewal can be created safely.

Connected profile/training changes now project current roster labels and stable-player training evidence into records in the same HTTP transaction. Actual HTTP regressions cover RSVP remaining unknown attendance, held present evidence, cancelled denominator exclusion, rollback of both documents on a failed record write, and preserving historical participation/config snapshots during current roster changes. The API owner reports 79 passing API/access/worker tests plus TypeScript/scoped lint at this checkpoint. A newly prepared fixture does not silently switch the report's live-match pointer: `live.context.set` remains an explicit manager API command, and the connected report editor still lacks the richer context/archive/correction controls.

## Open release gates

- **M0 physical feasibility:** no physical iPhone/Android report exists. An earlier managed-cloud Android attempt was blocked by its network policy. Independent standard public CI later compiled Android debug and unsigned iOS Simulator successfully for source `36223f7`; binaries were not retained. See the [actual native build evidence](evidence/2026-10-21/expanded/native-ci.json). See `android-build-evidence.md` and the native proof register.
- **Native-only behaviour:** SQLCipher activation/wrong-key rejection, SecureStore loss/backup exclusions, monotonic continuity across lock/reboot, process kill, foreground/background alerts, Focus/battery restrictions, camera/library permissions and credential/PIN lockout require actual devices.
- **Identity and operations:** Q05/Q10 ownership, recovery authority, verified adult sign-in, support/privacy/moderation owners, retention/deletion rules and operating budget remain open. Local drafts do not submit or fulfil account deletion/export.
- **Match policies:** Q06/Q07 practical timing/keeper/fairness defaults, Q08 control/reconciliation/background guarantees, Q09 attendance/excused handling, Q15 cutoff and Q18 exceptional results are not silently approved by implementing an experiment.
- **U10 publication:** Q21 requires the club/league competition/fixture-class audience decision. Default shared scores and derived summaries stay withheld. Synthetic illustrations/role selectors do not resolve the actual league or child-privacy operating questions.
- **Connected pilot:** the browser review's local feature documents must be integrated with the API/worker, authenticated projections/media retrieval, retries, exports, notifications and native device flows. Paid identity/storage/hosting services, store enrolments and production publication have not been provisioned by this feature work.
