# Full feature build and evidence register

Updated 21 October 2026. The supplied canonical pack, approved visual boards, native iPhone/Android target and full F01–F28 scope remain the target. This register distinguishes implemented source, actual runtime/browser evidence, unresolved product decisions and physical-device acceptance. It is not a release-complete claim.

## Current implementation

One Expo/React Native application serves native phones and a phone-sized React Native Web review export. Shared TypeScript packages hold match, planner, reporting and access rules. Node APIs support fictional SQLite development and actual PostgreSQL; separate workers handle awards, media and generic team notifications. Local runtime and identity rehearsals use fictional data. No hosted or paid service has been provisioned by this work.

The ordinary review opens fictional Roma data. Production entry uses OIDC/PKCE and verified API memberships. Native controller/workspace requests require actual encrypted-journal diagnostics; a real-account browser controller cache cannot mount. Real browser workspace DTOs/retries remain in memory. Protected canonical and ordinary workspace outboxes retain exact request bytes/key/revision, recheck authority before replay and await durable receipts. Scoped DTOs bind API, issuer, subject, account, team, season, role, player and request generation; lock, expiry and authoritative scoped denial close private views.

Connected preparation, profile snapshots, training attendance, own responses, reports, audited historical correction, accepted-match context/archive and filtered JSON/CSV export are implemented. Rollover requires explicit manager/admin/player assignments and recent stronger administrator authentication, creates no spectator grant and preserves source documents/memberships and active matches. Staff and global-account request controls are being integrated in the current source; their final browser/API acceptance remains pending. Request submission is separate from account export/deletion fulfilment.

## Outstanding work and decisions

- Complete final staff/account-request/album integration acceptance and the frozen-source browser/HTTP/build checks. Any remaining in-app report/award/album composition is implementation work, not a product-policy approval gate.
- M0 still needs actual iPhone/Android SQLCipher/wrong-key, SecureStore/key-loss/backup exclusion, process-kill, continuous-clock/reboot and native alert/picker/OIDC/share tests. Native compilation and browser tests do not establish these behaviours.
- Q05/Q09/Q10 require named adult/household verification, recovery, privacy/moderation/support and lifecycle owners, retention/deletion rules and budget. Request capture/status works without inventing fulfilment or instant erasure.
- Q06/Q07/Q08/Q15/Q18 retain unresolved timing/fairness/controller exceptions, background guarantees, cutoff and exceptional-result policy. Trial implementations do not approve product defaults.
- Q21 needs the actual club/league fixture-class audience decision. Shared scores, derived results, awards and contextual media remain withheld by default; no UI manager self-approval.
- Production identity/push/hosting/TLS/store accounts, operating signature updates, encrypted offsite backup, capacity/recovery targets and release ownership remain unconfigured or unaccepted. The isolated local provider/runtime proves capability, not live-child operating approval.
