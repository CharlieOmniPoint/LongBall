# Compatible frontend review deployment

The [compatible-frontend workflow](../../infra/cloud-preview/pages-compatible-frontend.yml) publishes a tested browser update against the existing bounded demo API. It preserves the native targets and adds no paid provider.

A pinned request lives at `frontend-review/request.json` on `preview/longball-m0`, outside backend-trigger paths. It names frontend/backend commits, the backend transport, actual API/worker SHA256 values and completed functional CI. The workflow requires successful functional/image stages and checks an exact Git diff for `apps/api`, `apps/worker`, `packages`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `scripts/build-api.mjs`, `infra/runtime`, `infra/cloud-preview/backend`, `apps/mobile/app.json`, `apps/mobile/package.json`, `apps/mobile/app.config.*` and `apps/mobile/plugins`. It verifies compiled API/worker bytes and the matching ready marker/active backend before publication. These checks allow the separately tested frontend UI to change; they do not establish a fresh native binary build. A known dependency-enforcement failure stays recorded; this workflow grants no release exception.
