# LongBall API

Runnable Node 24 HTTP API with a real asynchronous PostgreSQL adapter and an explicit fictional SQLite adapter. Both use the same HTTP boundary, permissions, pure match rules and application services. Native iPhone/Android remain the match-controller targets; browser review shares the business logic. No paid infrastructure is provisioned.

PostgreSQL uses parameterized SQL, JSONB documents, composite club/team/season foreign keys, row security, transaction-pinned connections and a conservative advisory transaction lock across API/worker processes. This first implementation serializes domain mutations; it does not claim production throughput. Real PostgreSQL HTTP tests cover cross-pool manager limits, fault rollback, durable controller history, clock exchange, immutable review proposals, training/season/report bridges and corrected archives. Physical-phone evidence and operating policies remain separate gates.

From the repository root:

```bash
LONGBALL_SYNTHETIC_AUTH=1 node --import tsx apps/api/src/main.ts
LONGBALL_SYNTHETIC_AUTH=1 node --import tsx apps/worker/src/main.ts --once
```

That fictional mode binds `127.0.0.1:4310`, persists `.local/api/longball.sqlite`, and accepts only loopback clients. Production refuses synthetic authentication and SQLite startup. Without a configured OIDC verifier, authenticated real-runtime routes fail closed. `/health` reports the actual backend and synthetic-authentication setting.

The real runtime reads `LONGBALL_DATABASE_URL` or `LONGBALL_DATABASE_URL_FILE`. Use distinct restricted API/worker roles, `LONGBALL_DATABASE_MIGRATION_MODE=verify`, and configured OIDC values. Apply all migrations first through `node --import tsx apps/api/src/migrate.ts` using only the dedicated `LONGBALL_MIGRATION_DATABASE_URL[_FILE]` selector and pre-created runtime roles. The API and worker reject production apply mode; feature schemas also verify without DDL. Keep credentials in ignored local files or mounted secrets. The local PostgreSQL fixture/CI harness creates disposable databases; it provisions no hosted database.

PostgreSQL startup rejects schema/table owners, superusers, roles that bypass row security, inherited privileged roles and mismatched API/worker purpose. Each verified issuer/subject lookup has a narrow identity context. Authenticated routes then install server-selected account, role, operation and resolved ancestry using transaction-local context. SQL transactions apply that context on their pinned connection; standalone statements use short transactions and clear it before returning the connection. Exports use the same selected audience and database scope. An absent context exposes no private rows. Unknown legacy club ancestry stays unresolved and unavailable until an operator supplies evidence. Runtime credentials cannot bootstrap fixtures; the disposable PostgreSQL fixture uses separate operator credentials before the restricted API starts.

Fictional bearer labels include `synthetic-manager-1`, `synthetic-manager-2` through `-5`, `synthetic-admin`, `synthetic-account-player-01` through `-13`, `synthetic-spectator` and `synthetic-other-manager`. These labels are deliberately public demonstration selectors, not secure credentials. The first manager maps to `synthetic-account-manager` and has explicit administrator plus manager assignments; three other Roma managers fill the remaining places. A fifth cannot be assigned. Never use this mode for real accounts, children or photos.

The generated review uses 13 named sample players, eight home/away fixtures and seven training dates from `fixtures/roma.synthetic.json`. Set `LONGBALL_DEMO_SCENARIO=1` only alongside synthetic authentication to expose the sample scores/results and a 45-minute post-match voting example. This opt-in is refused in production and leaves the real competition policy unapproved. The cloud review then runs `infra/cloud-preview/seed-demo-media.mjs` against loopback: it creates two published sample illustrations and one pending player submission through the normal upload, scanner, derivative and moderation pipeline. It cannot populate a non-demo API or publish when scanning is unavailable. The same command is idempotent; it does not overwrite user work or upgrade a pre-existing database into demo-sharing mode.

Team: `synthetic-roma-u10`. Season: `synthetic-season-2026-27`. Match: `synthetic-roma-maple-2026-10-24`. GET `/v1/me` returns the verified principal and current memberships. Every command derives its actor from that principal; body role/classification values cannot create authority.

## Implemented routes

| Route | Boundary |
| --- | --- |
| GET `/v1/matches/:id` | Current membership; server constructs manager/own-player/spectator DTO. No teammate named records for children, no participation for spectators. Q21 sharing defaults to manager only. |
| GET `/v1/matches/:id/download?deviceId=...` | Assigned verified manager; roster, projection, versions and durable device sequence checkpoint. UTC observation is explicitly **not** a proven continuous clock mapping. |
| POST `/v1/matches/:id/controller` | Acquire one account/device-bound capability. A second controller requires handover or audited recovery. |
| POST `/v1/matches/:id/events` | Ordered batches, maximum 100 and 256 KiB. Atomic event/sequence/projection/idempotency write, permanent event-ID deduplication, reducer validation and retained rejected branches. |
| POST `/v1/matches/:id/handover` and `/handover/:transferId/accept` | Explicit offer, write freeze, receiving manager/device and incremented epoch. Preparation, already-paused play and half-time work. Running transfer fails with `CLOCK_ANCHOR_REQUIRED`; no invented pause/time mapping. |
| POST `/v1/matches/:id/recover` | Recent verified adult authentication, explicit unsynchronised-history risk confirmation and reason. Preserves old records and flags running-clock reconciliation. |
| GET `/v1/matches/:id/quarantine` | Managers inspect retained rejected events/conflicting submissions. No automatic merge/discard or reconciliation approval route. |
| GET `/v1/matches/:id/reconciliation`, POST `/reconciliation/proposals` | Immutable retained source digests, accepted-state digest and concrete conservation-checked proposal. Preview IDs consume no controller sequence. Apply remains `503 Q08_AUTHORITY_UNAPPROVED`; proposals never approve their own reviewer authority. |
| POST `/v1/matches/:id/clock/challenges`, POST `/clock/challenges/:challengeId/acknowledge` | Current account/device/epoch capability, single-use challenge and durable receipt. Explicit trusted-time bounds are required; downloading a UTC observation never creates a continuous mapping. |
| GET `/v1/teams/:id/managers` | Current administrator with stronger authentication; scoped assignment history, distinct team-wide active count and already-associated verified adult candidates. No child profiles or global account directory. |
| POST `/v1/teams/:id/managers` | Current administrator, recent stronger authentication, verified adult target with stronger-authentication enrolment; transactional four-manager cap across team seasons. |
| POST `/v1/teams/:id/managers/revoke` | Explicit scoped administrator revocation and reason; freezes the departing controller, retains history and leaves other-season assignments intact. |
| GET/POST `/v1/teams/:id/configuration` | Safe club/team settings without private roster data. Manager team edits; administrator club edits with recent stronger authentication. |
| GET `/v1/teams/:id/seasons/rollover-options`, POST `/seasons` | Explicit verified manager/administrator/player assignments in one transaction; source documents stay intact, duplicate season years are refused and spectators receive no automatic renewal. |
| GET/POST `/v1/teams/:id/preparation` | Manager preparation/typed commands; club edits additionally require administrator assignment. Optimistic revisions prevent stale edits. |
| GET/POST `/v1/teams/:id/preparation/own` | Own linked profile, fixtures/training and own response/attendance only. Typed own response/ranked-preference commands cannot select another player or change manager-owned fields. |
| GET/POST `/v1/teams/:id/community` | Server-bound role/current grant, typed commands and server receipt time. Responses use `getCommunityView`, never raw ballot/private state. Cached receipts cannot bypass current access. |
| GET `/v1/teams/:id/community/media/:photoId` | Re-check illustration gallery/own/review permission on every request. Pending items unavailable to ordinary viewers. |
| POST `/v1/teams/:id/media/uploads/prepare`, PUT `/media/uploads/:uploadId`, POST `/media/uploads/:uploadId/complete` | Real bounded JPEG/PNG byte upload with SHA-256, private quarantine, configured scanner and isolated decode. No scanner means completion fails closed; metadata-only receipts never publish an image. |
| GET `/v1/teams/:id/media/photos/:photoId/display` or `/thumbnail` | Authenticated private byte gateway; current grant, review state, revision, hiding/removal and Q21 policy rechecked each time. Originals have no delivery route. |
| GET/POST `/v1/teams/:id/records` | Role-filtered results/own participation; manager writes. Live archive uses the accepted server match. A manager cannot approve open Q21 through a command. |
| GET `/v1/teams/:id/records/export` | JSON/CSV allowlisted report export for the selected current audience; stale projection/policy requests are refused. No raw editable state, teammate child records or ballots are exported. |
| GET/POST `/v1/privacy/requests` | Own request status and confirmed scope snapshots; explicit current team-season leave or all-membership export/deletion confirmation. Pending business requests deduplicate across new transport keys. No erasure or approval of Q05/Q09 by inference. |
| GET/POST `/v1/identity/devices` | Own native installation recognition, including accounts without team membership. Server-stamped observation times and reported platform grant no recorder authority. Legacy recorder metadata remains explicitly unknown. |
| GET `/v1/teams/:id/branding` | Current slot revisions, effective team override or live club fallback, current capabilities and only the author's authorised private uploads. |
| POST `/branding/:kind/uploads/prepare`, PUT `/branding/uploads/:uploadId`, POST `/branding/uploads/:uploadId/complete` | Seasonless supplied logo assets under a current authority season. Club upload requires selected administrator; team upload requires selected assigned manager. Scanning and isolated decoding produce private transparent PNG derivatives. |
| POST `/branding/:kind/publish` or `/remove`, GET `/branding/assets/:assetId/revisions/:revision/display` or `/thumbnail` | Exact reviewed revision, rights acknowledgement and optimistic slot version. Authenticated gateways recheck current pointer and access; originals and replaced assets have no published route. All paths have the `/v1/teams/:id` prefix. |
| GET/POST `/v1/teams/:id/spectator-invites`, POST `/:invitationId/reissue`, DELETE `/:invitationId` | Current manager or own linked player issues server-generated credentials. The raw share URL is returned once; retries return a redacted receipt. Revocation updates the normalised credential and grant projection atomically. |
| POST `/v1/spectator-invites/inspect` or `/accept` | Authenticated, membership-free token resolution. Inspect returns the actual destination before explicit acceptance; link metadata cannot choose the destination. |
| POST `/v1/spectator-invites/activation-info` or `/activate` | Bounded public original-capability exchange for a configured first-time spectator provider flow. Activation creates no membership, adult eligibility or session. Full sign-in and separate acceptance are required. |
| POST `/v1/teams/:id/activation/pending-child` and `/activation/issue` | Assigned manager; optional isolated provider port, immutable child classification, disabled pending account and one-time hash-only activation secret. Not configured by the CLI. |
| POST `/v1/activation/redeem` and `/complete` | Bounded public capability/proof exchange; provider handles credentials/recovery material. Completion requires a fresh full OIDC sign-in and creates no session. |
| POST `/v1/accounts/link-requests` and `/recovery-requests` | Scoped manager requests retained for independent verification; no automatic account adoption, password reset or membership transfer. |

POST requires bearer authentication, JSON, stable `Idempotency-Key` and `X-Api-Contract-Version: longball.events/1.1`, except the public activation capability/proof exchange which still requires the contract and idempotency headers. Read-only invitation inspect requires the contract header without an idempotency key. DELETE invitation revocation requires both mutation headers. Controller writes also require `X-Controller-Token` from acquisition. Store tokens securely, never in logs or public Expo configuration. Re-check current scope even for idempotent replay. Device sequences never reset across epochs; quarantined positions stay reserved.

Invitation creation and reissue accept `{seasonId,expiresInHours}` with an explicit integer from 1 to 48; their body is the authoritative season scope. Listing and deletion use the season query. Configure `LONGBALL_PUBLIC_APP_ENTRY_URL` and `LONGBALL_INVITATION_POLICY_VERSION` before issuance; an optional `LONGBALL_DEFAULT_INVITE_EXPIRY_HOURS` must be an explicit operator choice. Tokens contain 256 random bits and only domain-separated hashes are retained. Legacy plaintext credentials are retired without erasing accepted grant history. Connected legacy `invite.*` community commands are refused. A token-derived authenticated inspect or accept never trusts caller-supplied team IDs.

Native recognition accepts exactly `{deviceId,platform:'ios'|'android'}`. Registration and last-seen are actual server observations, while platform remains unverified. The inventory is a list of recognised identifiers, not an attested physical-device count or identity-provider session list. Remote revocation is unavailable. Native credentials and controller capabilities remain separate.

Supplied-logo publication accepts a captured `{command}` with its matching idempotency key, current rights policy, reviewed asset revision and expected slot version. Team slots inherit the club's current pointer immediately when no team override is present; neither slot is copied at season rollover. The selected authority season proves current permission but never becomes asset ancestry. Private upload capabilities are hashed and never enter generic receipt storage. PNG derivatives preserve alpha and strip metadata; ordinary photo derivatives retain their existing JPEG output.

Team receipt keys bind the season and selected role; replay under a different season cannot return an old private response. Spectator access is the union of current grants, intersected with SQL account/membership authority at every route. Revoking one invitation does not remove an independent valid grant, and revoking the last grant blocks match/results/media routes immediately.

Staff uses the explicit administrator role. The GET response includes an authoritative per-team-season `revision`; assigning/reactivating or revoking an assignment advances that ledger. The connected command body is `{command:{id,type:'manager.assigned',expectedRevision,accountId}}` or `{command:{id,type:'manager.revoked',expectedRevision,accountId,reason,confirmRevocation:true}}`, where `id` equals `Idempotency-Key`. Receipts include `commandId`, `revision` and server `acceptedAt`. Existing direct assignment/revocation bodies remain accepted. Revoking one season leaves other-season assignments and their contribution to the four-person cap intact. Known opaque target IDs can be submitted without searching a global directory.

Account requests accept exactly `{kind:'leave_team',teamId,seasonId,confirmLeave:true}` or `{kind:'export'|'delete_account',scope:'all_memberships',confirmAllMemberships:true}`. GET returns only that account's active, expired and revoked memberships plus retained requests. The affected memberships are captured at confirmation and remain unchanged. New keys for an existing pending account/kind/scope return its original request ID; exact retries still recheck current leave authority. Earlier unscoped leave requests become `needs_scope`; historical duplicate requests remain visible for review. No request automatically changes credentials, memberships, media or retained match records.

`fixture.prepared` creates the canonical match from the shared immutable profile/formation snapshot. An existing claimed or recorded stream is never reset to accept a changed preparation snapshot.

Profile and training changes project current roster labels and season-filtered training evidence into records inside the same mutation transaction. Stable player IDs connect the documents; availability replies never mark attendance, cancelled sessions remain retained and are excluded from denominators, and saved match participation/configuration snapshots stay unchanged. Own-player training replies update only their response evidence. Selecting another live report/archive context remains an explicit manager `live.context.set` command; preparing a different fixture does not silently switch an active report match.

Match reports and JSON/CSV exports join the current role-filtered community projection for that same account/team/season. They include only a sealed award summary and the count of photos in that viewer's permitted published album. Ballots, candidate lists, pending submissions and moderation state stay out of the report. Either report or community sharing restrictions withhold the joined fields, and hiding an uploader updates that viewer's album count.

The old preparation-only `season.rolled_over` command remains refused because it cannot assign authority. Use the dedicated `/seasons` command with its explicit assignment plan. Rollover creates addressable preparation/community/report documents, preserves the old season and copies no spectator grant. Historical corrections remain available through their audited route.

Accepted post-full-time participation corrections refresh the existing detailed archive under the same result identity, preserving previous archive audit and the immutable match snapshot even when another report context is selected. New accepted finish evidence creates a service-owned manager-only community context. Original full time requires a matching bounded continuous mapping; absent evidence remains review-required. Later eligibility changes, recovery or conflicting branches flag review without resetting the original timestamp, cutoff, +60 deadline or sealed award. No default voting cutoff is selected.

Schedule changes, accepted match revisions, photo publication/review and sealed awards enqueue opaque notification jobs in their domain transaction. Own replies, private votes and historical result edits are not broadcast. Workers recheck current membership, grants, preferences, quiet hours and the actual entity policy. The CLI has no configured push provider: eligible jobs become `blocked_provider`, never delivered. Explicit provider test doubles prove the queue protocol without claiming APNs/FCM delivery.

Real media uses `X-Media-Upload-Token` for PUT/completion; its short-lived write token is hashed in the manifest and never cached as a plaintext generic idempotency response. Configure a maintained ClamAV daemon through `LONGBALL_CLAMD_SOCKET` or `LONGBALL_CLAMD_HOST`/`LONGBALL_CLAMD_PORT`, or an absolute `LONGBALL_CLAMSCAN_PATH`; absence or unavailability fails closed. The local integration harness has exercised actual ClamAV with its signed database and PostgreSQL, without establishing production operation. Completion derives and strips metadata in a separate bounded process, then links the stable community command and media manifest inside one database transaction using fresh permissions/state. Pending bytes stay private; manager uploads still require explicit publication. JPEG/PNG are supported; HEIC remains unavailable until a tested decoder is selected. Scoped game parents support accepted and historical community matches without fabricating a native match stream. The private media directory must stay outside the browser export. A database-only backup does not back up media objects.

`contracts/events-v1.1.schema.json` is the deliberate C-001 companion. It requires immutable `engineVersion`; the archive stays unchanged. It adapts shared reducer commands and does not claim the original OpenAPI accepts an undeclared added field. Envelope effective time is the true event boundary, including late entries/correction targets; the replay checkpoint is separate. Unknown versions remain quarantined. The reducer validates typed transitions; this transport schema does not establish every original OpenAPI endpoint.

## Configured OIDC

Set trusted HTTPS `LONGBALL_OIDC_ISSUER`, `LONGBALL_OIDC_AUDIENCE` and `LONGBALL_OIDC_JWKS_URI`. The verifier checks RS256 signatures, cached RSA keys of at least 2048 bits, exact issuer/audience, expiry, not-before and subject. Unknown-key refresh is bounded. Strong authentication requires signed MFA/password+OTP evidence or an explicitly approved `LONGBALL_OIDC_MFA_ACR`; a bare hardware-key label is not assumed to prove user verification.

Signed claims do not assign application roles, promote children or establish adult eligibility. Issuer/subject mappings, account status, adult verification, stronger-authentication enrolment and memberships come from service records. Live bootstrap/household recovery authority, operator/provider configuration, exact redirects and tested device flows remain release gates. The explicit local provider trial creates no hosted identity service or live policy approval.

The SQLite `createApi` activation experiment requires synthetic authentication. PostgreSQL supports an explicitly injected provider adapter and versioned fictional policy; normal CLI startup leaves activation unconfigured. There is no implicit expiry choice or Q05 approval. The manager pending-child body is `{playerId}`, issue is `{accountId}`, with team path and season query; `Idempotency-Key` becomes the service request ID. Public redeem accepts `{token}` and complete `{activationId,token,completionProof}`. Completion requires the original capability before any provider lookup, then independently verifies the provider proof. The setup screen retains the original token in memory only; restarting requires entering it again. Link requests use `{teamId,seasonId,playerId,existingAccountId}`; recovery uses `{teamId,seasonId,accountId}`. Activation secrets are returned once, only hashes are retained, reissue cancels/tombstones older provider flows, and plaintext secrets/provider links never enter the generic receipt cache. Completion creates no session. Responses use `no-store` and `no-referrer`. A provider-specific local trial is separate from live-provider policy approval.

## One-origin browser export

```bash
LONGBALL_SYNTHETIC_AUTH=1 LONGBALL_API_PORT=4173 \
LONGBALL_STATIC_DIRECTORY=apps/mobile/dist-web \
node --import tsx apps/api/src/main.ts
```

Only permitted files inside the explicit export directory are served. Traversal, dotfiles and symlink escapes are refused. Only `/` resolves to `index.html`; unknown routes return 404. API authentication remains enforced. An explicitly configured reverse proxy may serve the fictional export/API; demonstration selectors still provide **no real-account security guarantee**. This server creates no tunnel, host or paid service.

## Persistence and limits

SQLite uses foreign keys, WAL and `BEGIN IMMEDIATE`; its asynchronous review facade serializes HTTP operations. Documents are scoped by team/season/kind with revisions. Neither server adapter is the encrypted native controller journal. SQLite has no PostgreSQL row-security guarantee. PostgreSQL migration `002_runtime.sql` plus subsequent numbered migrations implement the real runtime; `001_initial.sql` remains earlier preparation. Device identifiers are canonical text with a 120-character limit. Restricted-role HTTP/SQL tests exercise actual row security, context cleanup, cross-club exports and denied forged ancestry. Paired media/database restore and private-container harnesses record their own actual results; these local checks do not establish production load, monitoring, retention or disaster-recovery operation.

Run `node node_modules/vitest/vitest.mjs run --config apps/api/vitest.config.ts`. Tests cover OIDC denial, team isolation, child promotion/fifth-manager denial, stale epochs, handover sequence continuity, retry deduplication, fault-injected atomic rollback, effective versus recording time, pending media/expiry/DTO privacy, privacy requests, actual SQLite backup/reopen and static path denial. Worker tests cover explicit cutoffs, tied awards, unchanged deadlines, late finalisation and retained bounded retries.

Physical-device evidence, live provider/household recovery approval, running handover completion, Q08 reconciliation apply authority, remote push delivery and deployment operating policies remain gates. The fictional clock trial requires every bound explicitly in `LONGBALL_FICTIONAL_CLOCK_POLICY` JSON and is refused in production; it approves no live time or competition policy.
